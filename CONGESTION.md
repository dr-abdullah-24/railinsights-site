# Congestion analysis

Open `congestion.html` from the Analytics navigation or its Zone Congestion card.
The page uses the same TD/TRUST WebSocket bridge as Analytics. It does not supply
demo observations when a feed is unavailable.

## Deploy together

Publish the page and its three `assets/congestion*` files with the updated
`analytics.html`, `assets/rail-position.js` and `data/berth-quality.js`. The
Network Twin also consumes these shared position files. Restart/redeploy `server.js` alongside them: state payloads now
include `delayTs`, the bridge receipt time for the latest TRUST update, and TRUST
updates trigger a broadcast. Existing clients may ignore this additive field.
An older bridge remains supported: reported delays without timestamps are visible
and labelled “Age unknown”, including in CSV exports. No new package or credential is required.

## Interpretation

- Geographic clusters need three delayed services within 3 km of a seed, ranked
  by summed current lateness. They are indicators for investigation, not confirmed
  bottlenecks, track occupancy, capacity utilisation or delay attribution.
- Position age is adjustable. Timestamped delay reports must be at most 15 minutes old. Untimestamped reports
  remain visible with an unknown-age label.
  Feed snapshots older than 60 seconds are withheld. Receipt time does not establish
  the original event time when upstream delivery itself is delayed.
- The existing bridge uses headcodes as keys; reused headcodes, coarse berth
  coordinates limit precision. Unmapped berths now clear the coordinate instead of
  inheriting the previous location.
- Esri World Imagery supplies a satellite/aerial mosaic with attribution. It is
  historical geographic context, not live imagery. Acquisition dates are not
  inferred. OpenStreetMap is the alternate basemap.
- Headway, dwell, reactionary delay and recovery predictions need additional
  timetable/topology/event-history/incident inputs and are not estimated here.

## Verification

`node scripts/test-congestion.cjs` checks calculations, exclusions and thresholds.
For browser verification, serve the project on `127.0.0.1:8081`, set
`PLAYWRIGHT_PACKAGE` to an installed Playwright module, and run
`node scripts/verify-congestion-browser.cjs` (uses Chrome at its Windows install
path). Browser observations are intercepted fixtures, not live railway data.
Screenshots generated by this check are temporary review artifacts.

The map-first tracker defaults to all positive reported delays. Search by headcode,
location or UID, then select a service to follow incoming positions. Following is
paused when the service leaves the fresh selection and does not predict movement.

## Checked position pipeline

Run `node scripts/build-location-quality.cjs` to rebuild the checked lookup and
`data/location-audit.json`. This is deterministic and uses checked-in inputs;
`build-berth-positions.js` also runs it after its normal build/skip step.

- `data/location-overrides.json` documents corrections for Whiteball and Maidenhead.
  Whiteball uses the mapped tunnel centre, not a signal or individual berth.
- `data/railway-location-checks.json` contains local OSM railway geometry retrieved
  from the OSM API on 2026-09-12. It is © OpenStreetMap contributors, ODbL:
  https://www.openstreetmap.org/copyright . Each correction references its way/API.
- Other existing snapped positions are accepted only when within 250 m of their
  reference and within the geographic bounds. The existing dataset uses freight
  route geometry; these are labelled approximate route positions, not surveyed
  or GPS positions. Exact track identity is not established.
- Conflicting berth mappings over 500 m apart and unsupported coordinates are
  excluded from maps and geographic clustering, but delays remain in the list.
- This check does not prove that every remaining approximate route point lies on
  an individual track. Broader precise coverage requires verified berth/track data.

Run `node scripts/test-rail-position.cjs` for location and bridge regression checks.
No operator GPS access has been added or implied.
